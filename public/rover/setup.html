Enviro Rover / PI SETUP

From page to physical rover.

This page is a planner until you connect a real Pi service. The download includes the ESP32 firmware, ROS 2 bridge, camera service, web backend, frontend, tests, and the full WEB_SETUP.md guide.

↓ Download Pi software
Your camera is a view, not measured navigation.

Your encoderless tracks still need calibrated metric visual odometry or another motion-feedback source. The prior Gazebo map and sensors describe a simulated rover. Do not connect physical motors to that simulation. Free and blocked areas are read from a real Nav2 costmap.

01 / Extract on the Pi

cd ~
tar -xzf pi-package.tar.gz
cd ~/esp32_nav2

If your browser saved a different archive filename or used Downloads, adjust the path accordingly.

02 / Start the USB webcam service

On the Raspberry Pi OS host, outside Docker. PipeWire shares the USB camera with other desktop apps.

sudo apt-get update
sudo apt-get install -y python3-picamera2 python3-opencv python3-flask gstreamer1.0-tools gstreamer1.0-pipewire
cd ~/esp32_nav2
python3 camera_service.py --usb-node v4l2_input.platform-xhci-hcd.0-usb-0_1_1.0

Open http://127.0.0.1:8091 on the Pi for the full planner with local webcam preview. On a different USB port use the camera node.name from wpctl inspect. For CSI cameras omit --usb-node.

03 / Start real robot navigation

Configure and start physical-robot odometry, localization, Nav2 and the included bridge.py, following README.md. Use use_sim_time=false. Stop the older Tk route controller; use one mission controller at a time.

In a ROS 2 Jazzy Ubuntu environment/container, install:

sudo apt-get install -y python3-flask ros-jazzy-rclpy \
  ros-jazzy-nav2-msgs ros-jazzy-map-msgs ros-jazzy-tf2-ros-py \
  ros-jazzy-geometry-msgs ros-jazzy-nav-msgs \
  ros-jazzy-std-msgs ros-jazzy-std-srvs

Keep Ubuntu ROS packages inside the ROS container if the Pi host runs Raspberry Pi OS. Use host networking for the container so it can reach the loopback camera service. Copy the package into that prepared real-robot container. The full guide includes these steps.

04 / Start the authenticated web service

In the sourced ROS environment, from the extracted package directory:

source /opt/ros/jazzy/setup.bash
read -rs -p 'Web token (24+ random characters): ' ROVER_WEB_TOKEN
export ROVER_WEB_TOKEN
python3 web_server.py

Open http://PI_IP:8088 from a browser on the same LAN. Select Connect Pi and enter that address and the web token you chose. This local page is recommended for control. Hosted HTTPS pages require a trusted HTTPS Pi endpoint, an exact origin allowlist and browser local-network permission.

05 / Plan, check, then drive

  1. Confirm the physical room map and rover position are correct.
  2. Draw starting on the rover. Add stops and edit each wait time.
  3. Switch on Pi Camera to inspect the view.
  4. Use Check route. Unknown and high-cost areas are rejected.
  5. After supervised hardware commissioning, select Enable motors, then Start mission.
  6. Keep this tab connected and the physical power stop accessible. Stop rover applies motor hold and requests cancellation.

No-go rectangles additionally require Nav2 keepout filters in both costmaps and --keepout-enabled. The service refuses missions with unconfigured no-go zones. Consult WEB_SETUP.md before using them.

The browser control lease expires after five seconds without heartbeats. This requests a stop; it does not replace the independent ESP32 watchdog or physical motor-power stop. No real camera capture or physical drive has been verified by the automated checks.
